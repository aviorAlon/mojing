# 校验与评分

规则分布在三个模块：`app/validation.py`（照片和身材数据）、`app/fitting.py`（尺码与衣长）、`app/scoring.py`（可信度评分）。阈值目前按经验设定、偏宽松，积累真实用户数据后应当重新校准。

## 1. 照片检查（上传时）

用换装模型自带的姿态检测和人体解析完成，每张约 1 秒。

| 检查 | 结果 | 规则 |
|---|---|---|
| 分辨率 | 拦截 / 提示 | 短边 < 400 像素拦截，< 700 像素提示 |
| 清晰度 | 拦截 / 提示 | 拉普拉斯方差 < 15 拦截，< 50 提示 |
| 单人 | 拦截 | 检测到 0 人或多于 1 人 |
| 全身入镜 | 拦截 | 人物轮廓贴住画面上下边缘，或看不到脚踝 |
| 人太小 | 提示 | 人物高度不到画面的一半 |
| 视角 | 拦截 | 按"脸部像素占脸 + 头发的比例"区分正面和背面，按"肩宽 / 身高"识别侧面；和放的位置不一致就拦截 |
| 小腿被遮住 | 提示 | 膝盖以下裤子 / 裙子的像素多于皮肤 |
| 手臂被遮住 | 提示 | 手臂皮肤不到人物面积的 1% |

有照片被拦截时，整个上传都不会保存，页面在对应照片上显示原因。

## 2. 身材数据可信度

| 层级 | 规则 | 结果 |
|---|---|---|
| 单项范围 | 身高 120–220、体重 30–200、胸围 60–160、腰围 45–160、臀围 60–170、肩宽 28–60（cm / kg） | 超出：不可信 |
| BMI | 13–50 之外 | 不可信 |
| | 16–40 之外 | 存疑 |
| 围度关系 | 腰围比胸围和臀围都大 15cm 以上；腰围 / 身高不在 0.33–0.8；肩宽 / 身高不在 0.19–0.31 | 存疑 |
| 与照片对照 | 臀围和照片中的胯宽之比不在 2.2–4.2；BMI ≥ 35 但胯宽 < 36cm（≥ 30 时 < 31cm）；BMI ≤ 18.5 但胯宽 > 40cm；照片测得的肩宽和填写的相差超过 20–30% | 存疑 |
| 三视图之间 | 正面和背面的腿长比例相差 > 0.06；几张照片里衣服颜色差异大 | 存疑 |

最终等级：有任何"不可信" → `untrusted`；缺少必填项 → `unverified`；有"存疑" → `suspicious`；否则 `trusted`。不可信的数据不会用于挑尺码和计算衣长。

## 3. 尺码与衣长（fitting.py）

**挑尺码**：比较尺码表的成衣尺寸和身体尺寸加放量（胸围 +4、腰围 +0、臀围 +2cm；高弹面料再多给 6cm、微弹多给 2cm），选能穿下的最小码。上衣和连衣裙看胸围（连衣裙再看腰围），下装看腰围和臀围。

- 没有围度但有常穿尺码：用常穿尺码。
- 两者都没有：用中间码，并注明理由。
- 所有码都穿不下：用最大码，并提示可能偏紧。

**衣长**：有尺码表衣长和身高时，计算下摆位置（见 [架构说明](architecture.md#2-构建可重画区域build_agnostic)）；缺任何一项就不校准，并在评分里说明原因。

## 4. 可信度评分（scoring.py）

从 100 分往下扣，每一项扣分都附原因，分两部分：

**视觉可信度**：这张图能不能代表衣服穿在这个人身上的样子。

| 扣分 | 条件 |
|---|---|
| -20 | 衣服会露出小腿，但照片里小腿被遮住（腿部是推测的） |
| -15 | 衣服会露出手臂，但照片里手臂被遮住 |
| -15 | 照片没有经过质量检查 |
| -10 | 侧面 / 背面视角 |
| -10 | 商品图是模特上身图 / 模拟生成图 |
| -10 | 垂褶、蕾丝、镂空等复杂工艺 |
| -10 | 极速档 |
| -10 | 衣长没有按尺码表校准 |
| -5 | 印花、文字、条纹等细节；挂拍图；缺少衣长或袖型信息；照片模糊或分辨率偏低 |
| -3 | 标准档（相比精细档） |
| **质检** | 生成的衣长和尺码表偏差超过 5cm：按厘米数扣分，最多扣 30 |
| **质检** | 露出的腿比原照片细或粗超过 10%：按百分比扣分，最多扣 30 |

**合身判断依据**：数据够不够判断合不合身。身材数据不可信 -60、存疑 -20、缺失 -40；没有尺码表 -40；品类对应的关键围度没填，每项 -10；尺码表来自模拟或识别 -10；缺少弹力 -10；缺少版型、没有模特参考各 -5。

**总分** = 视觉 × 60% + 合身 × 40%，≥ 80 为高，60–79 为中，< 60 为低。

**质检一票否决**：任一项质检扣分 ≥ 20 分时，总分最高只给 59 分（低），页面显示红色的"质检未通过：原因"。

评分在生成前后各算一次：生成前根据数据给出预估（显示"待质检"），生成后加上质检结果（显示"已质检"）。
